# Протокол DHCP

## 1. Назначение и предпосылки
*   **Проблема:** Для работы сети каждому интерфейсу нужен IP-адрес. При ручной настройке администратор должен помнить, какие адреса заняты, а какие свободны. Это долго, утомительно и приводит к ошибкам (например, дублированию адресов).
*   **Решение:** DHCP (Dynamic Host Configuration Protocol) автоматизирует процесс конфигурирования. Он не только выдает IP-адрес, но и передает другие параметры: маску подсети, адрес шлюза по умолчанию, адрес DNS-сервера, доменное имя.
*   **Главное преимущество:** Централизованное управление адресами гарантирует отсутствие дублирования.

## 2. История развития (прародители DHCP)
*   **RARP (Reverse Address Resolution Protocol):**
    *   Появился более 30 лет назад.
    *   Принцип: Клиент посылает широковещательный запрос. Сервер находит MAC-адрес в базе и возвращает IP.
    *   Минусы: Нужен сервер в каждом сегменте сети, ручная регистрация MAC-адресов, нет передачи дополнительной информации.
*   **BOOTP (Bootstrap Protocol):**
    *   Создан для бездисковых станций.
    *   Плюсы: Передает доп. информацию (адрес TFTP-сервера, имя файла загрузки). Поддерживает **relay** (пересылку запросов главному серверу), что позволяет одному серверу обслуживать несколько сетей.
    *   Минусы: Таблицы настраиваются вручную, ограниченный размер доп. информации.
*   **DHCP:**
    *   Совместимое расширение BOOTP.
    *   DHCP-сервер поддерживает устаревших клиентов BOOTP, но не наоборот.

## 3. Режимы работы DHCP
DHCP-сервер может работать в трех режимах:
1.  **Ручное назначение статических адресов:**
    *   Администратор вручную привязывает IP-адрес к MAC-адресу клиента.
    *   Сервер всегда выдает этому клиенту один и тот же адрес.
2.  **Автоматическое назначение статических адресов:**
    *   Сервер сам выбирает адрес из пула при первом обращении клиента.
    *   Адрес закрепляется за клиентом навсегда (постоянное соответствие).
3.  **Автоматическое распределение динамических адресов:**
    *   Адрес выдается на ограниченное время — **срок аренды**.
    *   Если клиент уходит из сети, адрес освобождается и может быть выдан другому.
    *   Позволяет строить сеть, где количество узлов превышает количество доступных IP-адресов.
    *   *Пример:* 500 мобильных сотрудников, но в офисе одновременно бывает не более 50. Достаточно пула из 64 адресов и 64 рабочих мест.

## 4. Алгоритм динамического назначения адресов (DORA)
1.  **DHCP-поиск (Discover):** При включении компьютер-клиент посылает широковещательный запрос (IP-пакет с адресом назначения из одних единиц).
2.  **DHCP-предложение (Offer):** Все DHCP-серверы в сети получают запрос и отправляют клиенту свои предложения (IP-адрес + конфигурация). Если сервер в другой сети, ответ идет через **DHCP-агент (relay)**.
3.  **DHCP-запрос (Request):** Клиент выбирает первое предложение и отправляет широковещательный запрос с идентификатором выбранного сервера.
4.  **DHCP-квитанция (Ack):** Выбранный сервер подтверждает аренду. Остальные серверы аннулируют свои предложения и возвращают адреса в пул.
5.  **Рабочее состояние:** Клиент получает квитанцию и начинает работу.

## 5. Обновление аренды
*   Клиент пытается обновить параметры **задолго до истечения срока аренды**, обращаясь к тому же серверу.
*   Если сервер не отвечает, клиент повторяет попытки.
*   Если все попытки безуспешны, клиент обращается к другому серверу.
*   Если и другой отказывает — клиент теряет настройки и переходит в режим автономной работы.
*   Клиент может досрочно отказаться от аренды по своей инициативе.

## 6. Проблемы динамических адресов
*   **Проблема с DNS:** Сложно поддерживать таблицы соответствия символьных имен и постоянно меняющихся IP-адресов.
    *   *Решение:* Для серверов назначают статические адреса. Для больших сетей используют динамический DNS (согласование баз DHCP и DNS).
*   **Проблема с мониторингом и управлением:** Трудно удаленно управлять устройством и собирать статистику, если его IP постоянно меняется.
*   **Проблема с безопасностью:** Усложняется фильтрация пакетов по IP-адресам.
*   **Рекомендация:** Статические адреса назначают устройствам, которые предоставляют услуги и не меняют местоположение: маршрутизаторы, серверы, принтеры.
