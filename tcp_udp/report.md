# Транспортный уровень: TCP и UDP

Транспортный уровень в стеке TCP/IP отвечает за передачу данных между приложениями на разных хостах и использует **порты** (числа от 0 до 65535) для адресации процессов. **UDP** - это простой дейтаграммный протокол без установки соединения, без гарантий доставки и без сохранения порядка сообщений, зато быстрый и с минимальными накладными расходами; используется в DNS, DHCP, TFTP, SNMP и для потокового видео. **TCP** - это надёжный протокол с установкой соединения (трёхкратное рукопожатие SYN → SYN+ACK → ACK), нумерацией байтов, подтверждениями (ACK), повторной отправкой потерянных сегментов и управлением потоком через **скользящее окно**. 
Управление потоком предотвращает «затопление» медленного получателя (окно = 0 означает «стоп», отправитель шлёт Zero Window Probe), а управление перегрузкой (Slow Start, Congestion Avoidance, Fast Retransmit, Fast Recovery) не даёт перегрузить сеть. Размер окна TCP - это количество байтов, которые можно передать без подтверждения; подтверждение может быть **кумулятивным** (ACK на все предыдущие байты) или **выборочным** (SACK). 
Для завершения соединения используются флаги FIN (штатное закрытие) и RST (аварийный сброс). Заголовок TCP (20+ байт) содержит порты, порядковый номер, номер подтверждения, флаги (URG, ACK, PSH, RST, SYN, FIN), окно и контрольную сумму; заголовок UDP всего 8 байт. Динамические IP-адреса и порты усложняют мониторинг и фильтрацию, поэтому серверам и сетевым устройствам обычно назначают статические адреса. Главный вывод: **UDP - когда важна скорость, TCP - когда важна надёжность**.
