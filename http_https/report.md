# HTTP: основы, разбор запросов и ответов

## 1. Определения терминов

1. **HTTP (HyperText Transfer Protocol)** — это протокол, по которому браузер общается с сервером. Он нужен, чтобы запрашивать и получать данные: страницы, картинки, текст. Работает по схеме «запрос — ответ».

2. **HTTPS** — это тот же HTTP, но с шифрованием. Он защищает данные от посторонних глаз, подтверждает, что сайт настоящий, и не дает изменить информацию по пути. Работает на порту 443, а HTTP — на 80.

3. **Клиент-серверная модель** — это когда клиент (браузер или программа) отправляет запрос, а сервер его принимает, обрабатывает и возвращает ответ. Один сервер может обслуживать сразу много клиентов.

4. **Идемпотентность** — это когда повторение одного и того же запроса дает тот же результат, что и один раз. Например, если десять раз сказать «удали этот файл», файл удалится только один раз. Команды GET, PUT, DELETE — идемпотентны, а POST — нет.

## 2.1. Разбор запроса

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 58

{"name": "Иван", "email": "ivan@mail.com"}
```

1. **Метод:** POST. Он используется для создания новых данных.
2. **Путь:** /api/users. Это адрес, по которому мы работаем с пользователями.
3. **Версия:** HTTP/1.1.
4. **Content-Type:** application/json. Говорит серверу, что данные внутри написаны в формате JSON.
5. **Authorization:** Bearer... Это токен доступа. Он нужен, чтобы сервер понял, кто мы и можно ли нам это делать.
6. **Тело запроса:** это строка с данными `{"name": "Иван", "email": "ivan@mail.com"}`. Она идет после пустой строки. Параметр Content-Length: 58 указывает длину этих данных в байтах.

## 2.2. Разбор ответа

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{"id": 42, "name": "Иван", "email": "ivan@mail.com"}
```

1. **Статус 201:** Created. Означает, что данные успешно созданы.
2. **Location:** /api/users/42. Это ссылка на только что созданного пользователя. По ней можно сразу перейти.
3. **Тело ответа:** это данные созданного пользователя, включая новый id 42.

## 2.3. Составление запросов

### 1. Получить список всех товаров

```http
GET /api/products HTTP/1.1
Host: example.com
Accept: application/json
```
Метод GET просто читает данные и ничего не меняет.

### 2. Создать новый товар

```http
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <токен>
Content-Length: <длина_тела>

{"name": "Ноутбук", "price": 50000}
```
Метод POST создает новый товар, а данные передаются в теле запроса.

### 3. Удалить товар с id=7

```http
DELETE /api/products/7 HTTP/1.1
Host: example.com
Authorization: Bearer <токен>
```
Метод DELETE удаляет товар, его id указывается прямо в пути.

### 4. Обновить товар с id=3

```http
PUT /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <токен>
Content-Length: <длина_тела>

{"name": "Ноутбук", "price": 45000}
```
Метод PUT полностью заменяет данные товара. Если нужно поменять только цену, используют метод PATCH:

```http
PATCH /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <токен>
Content-Length: <длина_тела>

{"price": 45000}
```
